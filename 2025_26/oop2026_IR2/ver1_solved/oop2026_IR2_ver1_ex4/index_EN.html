Complete the PaymentOverview class, which represents an overview of one person’s bill payments. An object of this class contains a list of bills, sorts them according to the due date of their first installment, and enables iteration over all payments resulting from those bills.

The fully implemented classes Bill and Payment are provided and must not be modified. The MainClass class, which can be used to test the program code, is also provided. All these classes are located in the hr.fer.oop package.

The Bill class represents a bill and contains its description (description), the amount of each installment (installmentAmount), the total number of installments (installmentCount), and the due date of the first installment (firstDueDate). Appropriate getter methods are provided for all these attributes.

The Payment class represents the payment of one installment of a bill. It contains the Bill bill attribute, which represents the bill to which the installment belongs, and the LocalDate dueDate attribute, which represents the due date of that installment. Appropriate getter methods are provided for all these attributes. For a bill paid in n installments, there will be n objects of type Payment. The due date of the first payment is equal to the firstDueDate of the corresponding bill, while the due date of each subsequent payment is increased by one month. All installments of a particular bill have the same amount.

For example, for the following bill:

Bill bill = new Bill(
        "Electricity bill", 40.0, 3,
        LocalDate.of(2026, 11, 10)
);

the following three payments exist:

new Payment(bill, LocalDate.of(2026, 11, 10));
new Payment(bill, LocalDate.of(2026, 12, 10));
new Payment(bill, LocalDate.of(2027, 1, 10));

You may assume that the number of installments of every bill is greater than zero and that no two bills have the same due date for their first installment.

The PaymentOverview class

The PaymentOverview class contains a list of bills for which the payment overview is created. The following constructor is provided in the template:

public PaymentOverview(List<Bill> bills)

The constructor creates a copy of the provided list and sorts it in ascending order according to the due date of the first installment.

Bill comparator

Implement the following comparator:

public static final Comparator<Bill> BY_FIRST_DUE_DATE

The comparator compares bills in ascending order according to the due date of their first installment (firstDueDate).

Lambda expression for creating payments

Implement the following lambda expression:

public static final Function<Bill, List<Payment>> PAYMENTS_FOR_BILL

The lambda expression receives one bill and returns a list of its payments. To increase a due date by a specified number of months, you may use the plusMonths(long monthsToAdd) method of the LocalDate class.

The returned list must be mutable.

Iterating over payments

The PaymentOverview class must support iteration over objects of type Payment.

The iterator must be implemented using a private static nested class named PaymentIterator with the following declaration:

private static class PaymentIterator implements Iterator<Payment>

Reminder: Iterable<T> is an interface containing the Iterator<T> iterator() method, which returns an implementation of the Iterator<T> interface. The next() method from the Iterator<T> interface must throw a NoSuchElementException if it is called after the end of the iteration has been reached.

The iterator traverses individual objects of type Payment according to the order of bills in the bills list of the PaymentOverview object. Since the bills in this list are sorted according to the due date of their first installment, the iterator first returns all payments of the bill with the earliest first installment due date, followed by all payments of the next bill, and so on.

The list of payments for the current bill can be created by applying the previously implemented PAYMENTS_FOR_BILL lambda expression. Payments from the resulting list are returned one at a time. The iterator proceeds to the payments of the next bill only after all payments of the current bill have been returned.

Each element of the iteration is an individual object of type Payment. Therefore, the iterator must be of type Iterator<Payment>, not Iterator<List<Payment>>.

Usage example

The following code is provided in the MainClass class:

public static void main(String[] args) {
    List<Bill> bills = List.of(
            new Bill("Internet bill", 30.0, 2,
                    LocalDate.of(2026, 12, 5)),
            new Bill("Water bill", 15.0, 1,
                    LocalDate.of(2027, 1, 20)),
            new Bill("Electricity bill", 40.0, 3,
                    LocalDate.of(2026, 11, 10)));

    PaymentOverview overview = new PaymentOverview(bills);

    System.out.println("Payment overview:");
    for (Payment payment : overview) {
        Bill bill = payment.getBill();

        System.out.printf(
                Locale.US,
                "%s | %.2f EUR | due %s%n",
                bill.getDescription(),
                bill.getInstallmentAmount(),
                payment.getDueDate());
    }
}
