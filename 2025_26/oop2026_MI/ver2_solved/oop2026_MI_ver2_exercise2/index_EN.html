In this exercise you need to implement a robot that navigates a warehouse grid by executing a simple command language. The warehouse is a grid (width × height), and the robot explores it by moving, rotating, and scanning. Valid positions are [0, width) on the X axis and [0, height) on the Y axis. The supported robot commands are:

  • MOVE <steps> — Move steps steps in the current direction.
  • ROTATE <direction> — Rotate to the given direction. Valid values correspond to the Direction enum.
  • SCAN — Scan the current location and print robot state along with the scanned value. The scanned value is a random integer from [0, width * height), where width and height are the grid dimensions.

Example robot program (comments are informational only, your code does not need to handle them):

MOVE 1        // Move 1 step in the current direction (north)
ROTATE WEST   // Rotate to face west
MOVE 3        // Move 3 steps west
SCAN          // Scan current location and print
ROTATE EAST   // Rotate to face east
MOVE 5        // Move 5 steps east
SCAN          // Scan current location and print

DeployedRobot receives programs as multi-line strings and executes each line as a command. On an error in one line, the robot continues executing the remaining lines. The required methods are shown in the UML diagram.

The Robot class is already fully implemented, while the Warehouse and DeployedRobot classes are partially complete. In Warehouse you need to implement the methods scanAt(int x, int y) and move(DeployedRobot robot, int x, int y). In DeployedRobot you need to implement executeProgram(String program) - the method which actually executes the commands. The details of those methods are given further in the text.

In all classes you need to implement the attributes, constructors, and methods shown in the diagram.

Access modifiers in class diagrams:

Class Warehouse (provided, partially)

A warehouse is a rectangular grid of size width × height. Coordinates are 0-based: valid positions are [0, width) on the X axis and [0, height) on the Y axis. You must complete the move and scanAt methods.

You need to implement:

  • Method move(DeployedRobot robot, int moveX, int moveY):
    • Computes the new robot position for the given X and Y offsets.
    • Throws OutOfBoundsException(width, height, x, y) if the new position is out of bounds.
    • Otherwise updates the robot's position.
  • Method scanAt(int x, int y):
    • Throws OutOfBoundsException(width, height, x, y) if the position is out of bounds.
    • Otherwise returns a random integer from [0, width * height).

Class Robot (provided, fully)

Robot holds only robot identity (name and battery capacity). The deployAt method creates a DeployedRobot that holds state and executes commands.

  • Method deployAt(Warehouse warehouse, int startX, int startY, Direction startDirection):
    • Throws IllegalArgumentException if warehouse is null.
    • Returns a new DeployedRobot with starting position (startX, startY), direction startDirection, and battery at full capacity.
  • Methods deployAt(Warehouse warehouse) and deployAt(Warehouse warehouse, int startX, int startY):
    • Same as above, but set default values.

Class DeployedRobot (provided, partially)

DeployedRobot represents a single robot walk through the warehouse. It holds all robot state (warehouse, position, battery, direction) and implements the command interpreter. The class skeleton (constructor, getters, setters) is provided — you implement executeProgram.

executeProgram(String program) — executes a multi-line program:

  • Splits on newline characters. Before executing a line, strips the whitespaces at the start and end. Blank lines are part of the robot's program, but do not trigger a command.
  • IMPORTANT: Each line may throw a RobotException; the robot continues executing subsequent lines. These exceptions are stored in a CompositeRobotException such that the position in the errors array equals the line index (0-based) where the exception occurred. Successfully executed lines have null at their index. After all lines execute, if any errors occurred, a CompositeRobotException is thrown. The empty lines are also included in the errors array, at appropriate indices, but with null values.

Supported commands:

Command Battery cost Description
MOVE [n] n Move n steps (default 1) in the current direction. On success, decrements batteryLevel by n.
ROTATE <direction> 1 + |ANGLE|/90° (see table below) Change direction to NORTH, EAST, SOUTH, or WEST. Energy cost depends on the rotation type (see table below). Possible angles are [0°, -90°, 90°, 180°]. On success, sets the new direction and decrements batteryLevel by the cost.
SCAN 1 Prints robot state and scanned value via warehouse.scanAt(posX, posY): "Robot <name> at (<x>,<y>) facing <direction> in <warehouseName> scanned: <value>". Decrements batteryLevel by 1.

Rotation cost:

Rotation type Example Cost
Same direction NORTH ↔ NORTH, SOUTH ↔ SOUTH 1
Adjacent direction (±90°) NORTH ↔ EAST, SOUTH ↔ EAST 2
Opposite direction (180°) NORTH ↔ SOUTH 3

Movement directions: NORTH→+Y, SOUTH→−Y, EAST→+X, WEST→−X.

Grid bounds: Valid positions are [0, width) on the X axis and [0, height) on the Y axis.

Exceptions

All task-related exceptions are in the package hr.fer.oop.warehouse.exception.

  • RobotException is a checked exception and cannot be instantiated directly.
  • Every unrecognized command or invalid command argument throws InvalidCommandException.
  • Before executing a command and draining the battery, OutOfEnergyException(command, batteryLevel, requiredEnergy) may be thrown if there is not enough energy, i.e. if batteryLevel < requiredEnergy. The robot's battery cannot drop below 0. The robot state (battery level, position and direction) change only if the command executes successfully.
  • The MOVE command may throw OutOfBoundsException — for a given offset that leads outside the warehouse grid boundaries.
RobotException  (cannot be instantiated directly)
  ├── CompositeRobotException  (stores: RobotException[] errors)
  ├── OutOfBoundsException     (stores: width, height, newX, newY)
  ├── OutOfEnergyException     (stores: command, batteryLevel, requiredEnergy)
  └── InvalidCommandException  (stores: command)

Objects of the RobotException class cannot be instantiated directly. It has a single constructor: RobotException(String message).

CompositeRobotException holds the per-line error array from executeProgram. Slots for successfully executed lines are null.

Usage example

Robot roby = new Robot("Roby", 100);
Warehouse warehouseB = new Warehouse("Skladiste B", 50, 50);
DeployedRobot dr = roby.deployAt(warehouseB);
dr.executeProgram("""
    MOVE 3
    ROTATE EAST
    MOVE 3
    ROTATE SOUTH
    MOVE 2
    SCAN
    """);

Step-by-step robot state (starting at (0,0) facing NORTH, battery=100):

Command Position Direction Battery
(initial) (0,0) NORTH 100
MOVE 3 (0,3) NORTH 97 (−3)
ROTATE EAST (0,3) EAST 95 (−2, adjacent)
MOVE 3 (3,3) EAST 92 (−3)
ROTATE SOUTH (3,3) SOUTH 90 (−2, adjacent)
MOVE 2 (3,1) SOUTH 88 (−2)
SCAN (3,1) SOUTH 87 (−1)

Expected SCAN output (scanned value is random and may vary):

Robot Roby at (3,1) facing SOUTH in Skladiste B scanned: 42

Example program with errors:

Robot roby = new Robot("Roby", 100);
DeployedRobot walk = roby.deployAt(new Warehouse("W", 5, 5));
try {
  walk.executeProgram("""
      MOVE 3

      ROTATE RIGHT
      LAUNCH
      MOVE 10
      SCAN
      """);
} catch (CompositeRobotException e) {
  System.out.println("Program finished with errors:");
  RobotException[] errors = e.getErrors();
  for (int i = 0; i < errors.length; i++) {
    if (errors[i] != null) {
      System.out.println("  Line " + (i + 1) + ": " + errors[i]);
    }
  }
}

Expected output (scanned value varies - it is random):

Robot Roby at (0,3) facing NORTH in W scanned: 10
Program finished with errors:
  Line 3: hr.fer.oop.warehouse.exception.InvalidCommandException
  Line 4: hr.fer.oop.warehouse.exception.InvalidCommandException
  Line 5: hr.fer.oop.warehouse.exception.OutOfBoundsException

EXPLANATION - We create the walk with the deployAt(Warehouse warehouse) method, meaning its starting position is (0, 0), facing NORTH. The command on line 1 (MOVE 3) moves the robot 3 steps north to (0, 3) and decreases its batter level by 3. Line 2 is empty so nothing gets executed. On line 3, the ROTATE RIGHT is not valid because RIGHT is not a valid direction. We store the error. On line 4 LAUNCH is not a valid command - stored. On line 5 we move outside of the grid (which is 5x5) and get an OutOfBoundsException - stored. And lastly, since only the first MOVE went through we are still at (0, 3), facing NORTH, and scanned a random number 10; decrease the robots battery level by 1 (because of the SCAN).

Note: All classes have public visibility.
