U zadatku je potrebno implementirati interpreter jednostavnog programskog jezika zasnovanog na stogu naziva StackLang.

Zadana je klasa Stack koja radi s objektima (klasa Object) — potrebno ju je parametrizirati s generičkim tipom. Osim toga, potrebno je implementirati hijerarhiju iznimki te logiku interpretera StackLangInterpreter.

Stog radi po principu LIFO (Last In, First Out) — zadnji ugurani element prvi se uzima. To ostvaruje pomoću dvije metode:

  • push - Postavlja vrijednost na vrh stoga
  • pop - Uklanja element s vrha stoga i vraća ga kao rezultat.

Primjer:

  push(10)     push(20)     push(30)      pop()        pop()
                                        vraća: 30    vraća: 20
 ┌────────┐   ┌────────┐   ┌────────┐   ┌────────┐   ┌────────┐
 │        │   │        │   │   30   │   │        │   │        │
 │        │   │   20   │   │   20   │   │   20   │   │        │
 │   10   │   │   10   │   │   10   │   │   10   │   │   10   │
 └────────┘   └────────┘   └────────┘   └────────┘   └────────┘

Jezik na stog postavlja brojeve, koje možemo zbrajati i množiti. Primjer jednog StackLang programa (komentari su informativni, nisu dio samog jezika):

PUSH 10   // Stavi 10 na vrh stoga - stanje: [10]
PUSH 30   // Stavi 30 na vrh stoga - stanje: [10, 30]
MUL  3    // Pomnoži vrh sa 3      - stanje: [10, 90]
ADD       // Zbroji dva elementa na vrhu stoga - [10, 90] => stanje: [100]
PRINT     // Ispisuje stanje na stogu, ne mijenja stanje -> [100]

U UML dijagramu klasa prikazane su klase koje je potrebno implementirati. U svim klasama je potrebno implementirati atribute, konstruktore i metode kako su prikazane na dijagramu.

Vidljivost u dijagramima klasa:

Klasa Stack (paket hr.fer.oop.stack)

Klasa Stack implementira stog fiksnog kapaciteta, ali koristi Object umjesto generičkog tipa. Potrebno je promijeniti metode push i pop tako da vraćaju tip dan kao parametar:

Napomena: Java ne dopušta polja generičnih tipova, stoga polje stack mora ostati Object[]. Upozorenje o nekontroliranom castu možete potisnuti s @SuppressWarnings("unchecked").

Metoda push(T value) baca CapacityException(capacity) ako je stog pun, gdje je capacity maksimalni kapacitet stoga.

Metoda pop() baca EmptyException() ako je stog prazan.

Obje iznimke stoga CapacityException i EmptyException su neprovjeravane. Morate ih baciti kod prikladnih rubnih slučajeva u metodama push i/ili pop. Metode push i pop moraju u svojoj deklaraciji (potpisu metode) naznačiti pozivatelju da se odgovarajuća iznimka može dogoditi - CapacityException i/ili EmptyException.

Hijerarhija iznimki interpretera

Sve iznimke vezane uz StackLang interpreter nalaze se u paketu hr.fer.oop.stacklang.exception.

Klasa StackLangException je provjeravana iznimka koja se ne može instancirati. Potrebno je implementirati:

  • konstruktor StackLangException(int line) koji pamti broj retka
  • konstruktor StackLangException(Throwable cause, int line) koji pamti uzrok i broj retka
  • metodu getLine() koja vraća pohranjeni broj retka (redovi su numerirani od 1, uključujući i prazne retke)

Klasa CommandException nasljeđuje StackLangException. Baca se kada izvršavanje poznate naredbe ne uspije zbog nekog uzroka cause. Prema tome, kod bilo kakve pogreške u učitavanja ili izvršavajnu naredbe, CommandException omotat će tu pogrešku i javit o kojoj naredbi je bilo riječ. Potrebno je implementirati:

  • konstruktor CommandException(Throwable cause, int line, StackLangCommand command) koji pamti naredbu, uzročnu pogrešku i liniju na kojoj se dogodila pogreška.
  • metodu getCommand() koja vraća pohranjenu naredbu

Klasa UnsupportedCommandException nasljeđuje StackLangException. Baca se kada se naiđe na nepoznatu naredbu. Potrebno je implementirati:

  • konstruktor UnsupportedCommandException(int line, String command) koji pamti naziv naredbe
  • metodu getUnsupportedCommand() koja vraća pohranjeni naziv naredbe

Klasa NotEnoughArgumentsException (paket hr.fer.oop.stacklang.exception)

Neprovjeravana iznimka koja se baca kada naredba dobije premalo argumenata. Nije direktan dio hierarhije (ne nasljeđuje StackLangException). Potrebno je implementirati:

  • konstruktor NotEnoughArgumentsException(int numOfArguments, int expectedNumOfArguments) koji pamti oba broja
  • konstruktor NotEnoughArgumentsException(int expectedNumOfArguments) koji postavlja numOfArguments na 0
  • metodu getNumOfArguments() koja vraća stvarni broj primljenih argumenata
  • metodu getExpectedNumOfArguments() koja vraća očekivani broj argumenata

Višak argumenata

U slučaju kada interpreter primi komandu sa viškom argumenata, taj se višak ignorira. Npr. za primljenu liniju PUSH 1 2 3, uzima se u obzir samo PUSH 1, a ostali argumenti se ignoriraju, program regularno izvrši naredbu i nastavlja. Ovo vrijedi za sve podržane naredbe.

Klasa StackLangInterpreter (paket hr.fer.oop.stacklang)

Interpreter prima StackLang program kao String s više redaka. Svaki redak je jedna naredba. Praznine na početku i kraju retka se ignoriraju. Redovi se broje od 1. Prazni redovi se ne smatraju greškom, samo nemaju nikakav efekt, tj. za praznu liniju se ne izvrši nijedna komanda.

Podržane naredbe:

Naredba Opis
PUSH v Parsira v kao cijeli broj i stavlja ga na stog
PRINT Ispisuje trenutno stanje stoga na standardni izlaz koristeći već implementiranu `toString()` metodu u klasi `Stack`
ADD Skida dva broja s vrha stoga i stavlja njihov zbroj
MUL n Skida broj s vrha stoga, množi ga sa skalarom n i stavlja rezultat

Ako bilo koja naredba ne uspije, baca se CommandException gdje:

  • cause je iznimka zbog koje naredba nije uspijela. Uzrok problema zbog kojeg se naredba nije uspiješno izvršila.
  • line je broj retka naredbe koja se nije uspijela izvršit.
  • command je naredba koja se nije uspijela izvršit.

Ako se naiđe na nepoznatu naredbu, baca se UnsupportedCommandException(line, commandName).

Primjer korištenja

StackLangInterpreter interpreter = new StackLangInterpreter(1024);
interpreter.runProgram("""
        PUSH 10
        PUSH 20
        PUSH 30
        PUSH 40
        PRINT
        ADD
        ADD
        MUL 3
        PRINT
        """);

Primjeri s greškom:

  try {
   new StackLangInterpreter(10).runProgram("ADD");
  } catch (StackLangException e) {
   System.out.println("Greška u naredbi na retku " + e.getLine() + ", " + e);
   System.out.println("Uzrok: " + e.getCause());
  }

Očekivani ispis:


Greška u naredbi na retku 1, hr.fer.oop.stacklang.exception.CommandException: hr.fer.oop.stack.EmptyException
Uzrok: hr.fer.oop.stack.EmptyException

   try {
      new StackLangInterpreter(10).runProgram("""
          PUSH 3
          MUL 3 4 5

          PRINT
          PUSH
          PRINT
          """);
    } catch (StackLangException e) {
      System.out.println("Greška u naredbi na retku " + e.getLine() + ", " + e);
      System.out.println("Uzrok: " + e.getCause());
    }

Očekivani ispis:

SL Program Stack:
9
Greška u naredbi na retku 5, hr.fer.oop.stacklang.exception.CommandException: hr.fer.oop.stacklang.exception.NotEnoughArgumentsException
Uzrok: hr.fer.oop.stacklang.exception.NotEnoughArgumentsException

Objašnjenje - U retku 1, naredba PUSH izvrši se regularno. U drugom retku ignoriramo dodatne argumente 4 5 koji su nepotrebni i množimo 3*3. Redak 3 je prazan i ne izvršava se ništa. Zatim, u retku 4 ispisujemo stanje stoga i u retku 5 nismo dali potreban argument metodi PUSH, zbog čega se dogodio NotEnoughArgumentsException i uzrokovao CommandException koji ga je omotao.

Napomena: Sve klase i iznimke su public.
