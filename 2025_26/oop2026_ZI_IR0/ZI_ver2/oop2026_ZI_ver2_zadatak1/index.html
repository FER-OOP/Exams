U stablu direktorija nalaze se brojne log datoteke (.log) koje bilježe rad nekog sustava. Potrebno je obići stablo direktorija i analizirati sve .log datoteke kako bi se utvrdilo u kojima su zabilježene greške.

Svaki redak log datoteke započinje razinom zapisa (INFO, WARN ili ERROR), a redak koji započinje s ERROR predstavlja zabilježenu grešku. Za svaku log datoteku (tj. datoteku čija je ekstenzija isključivo .log) potrebno je prebrojati koliko redaka započinje s ERROR. Datoteku smatramo kritičnom ako ukupan broj grešaka prelazi 5.

Za obilazak stabla direktorija potrebno je napisati klasu LogVisitor koja (izravno ili neizravno) implementira sučelje FileVisitor.

Klasa LogVisitor mora implementirati sljedeće javne metode:

  • int getTotalErrors() - vraća ukupan broj redaka s greškom (ERROR) u svim pregledanim log datotekama,
  • String getWorstFile() - vraća punu putanju do datoteke s najvećim brojem grešaka (pogledati primjer i napomenu na dnu),
  • Collection<String> getCriticalFiles() - vraća abecedno sortirane nazive datoteka koje se smatraju kritičnima.

Potrebno je i dopuniti klasu Main koja je djelomično napisana. Potrebno je napisati statičku metodu

void callVisitor(Path startDir, FileVisitor<Path> visitor)

u kojoj se pomoću visitora obilazi stablo direktorija i računaju tražene vrijednosti. Ako prilikom poziva visitora dođe do iznimke, potrebno je pozvati metodu printStackTrace() odgovarajuće klase iznimke.

Klasa treba biti u paketu hr.fer.oop.

VAŽNO: Za rad s datotekama obavezno koristiti klasu java.nio.file.Path !

VAŽNO: U obzir uzeti samo datoteke s ekstenzijom .log. Sve ostale datoteke potrebno je zanemariti.

VAŽNO: Redak predstavlja grešku samo ako započinje s ERROR.

VAŽNO: Možete pretpostaviti da neće biti dvije datoteke s istim (najvećim) brojem grešaka.

VAŽNO: Možete pretpostaviti da su sve datoteke ispravno formatirane te da neće doći do pogreške ili iznimke prilikom obilaska stabla direktorija.

Primjer .log datoteke:

WARN	Switching to backup database
ERROR	Backup database unavailable
INFO	Activating offline mode

Primjer pokretanja:

Primjer poddirektorija u src/main/resources/:
-- logs_10_3			
------ connection.log		// 7 ERRORS
-- logs_11_3	
------ A_Server
---------- access.log		// 6 ERRORS
---------- permissions.log	// 0 ERRORS
------ queries.log		// 5 ERRORS

	Path startDir = Path.of("src/main/resources/");
	LogVisitor visitor = new LogVisitor();

	callVisitor(startDir, visitor);

	System.out.println("Total errors: " + visitor.getTotalErrors());
	System.out.println("Worst file: " + visitor.getWorstFile());
	System.out.println("Critical files: ");
	for (String path : visitor.getCriticalFiles()) {
		System.out.println(path);
	}

Očekivani izlaz:

Total errors: 18
Worst file: src/main/resources/logs_10_3/connection.log
Critical files: 
access.log
connection.log

NAPOMENA: Razdjelnik putanje ovisi o operacijskom sustavu — na Windowsu će se Worst file ispisati kao src\main\resources\logs_10_3\connection.log. (Ispis putanja u vašem rješenju mora biti neovisan o operacijskom sustavu tj. ispravno raditi na bilo kojoj platformi.)
